# Dtoon 개인용 폴드 앱 — 구현 및 빌드 안내

이 패키지는 **수정한 소스 코드**입니다. 현재 APK는 포함하지 않습니다.
Android 앱 전체 컴파일·설치·실기기 검증이 끝나기 전에는 기존 애니요미를 삭제하지 마세요.

## 반영한 조건

| 요구 사항 | 코드의 동작 |
|---|---|
| 기존 애니요미와 동시 설치 금지 | 원본과 같은 앱 ID `xyz.jmir.tachiyomi.mi`를 유지하고 debug·preview·benchmark의 별도 ID 접미사를 제거 |
| 개인용 앱 | 임시 이름 Dtoon, 별도 책 아이콘, 공식 앱 자동 업데이트 검사 비활성화, arm64 전용 APK 빌드 |
| 최신·인기 한눈에 | 영상·만화의 각 소스에 기본 최신·인기 개요 화면 추가. 두 실제 목록을 독립적으로 요청하고 한 화면에 표시 |
| 접힌 화면 | 최신·인기를 위아래로 배치. 작은 표지 그리드, 각 목록 독립 스크롤·재시도·전체 보기 |
| 펼친 화면 | 넓고 충분한 높이가 있는 창에서는 최신·인기를 좌우로 배치. 전환 시 두 그리드의 스크롤 상태 유지 |
| 만화 두 쪽 모아보기 | 가로 페이지 뷰어에서 서로 다른 두 페이지를 나란히 표시. 좁은 창으로 바뀌면 한 쪽 표시 |

## 두 쪽 보기의 세부 동작

- 설정 → 만화 뷰어의 읽기 모드 설정에 `넓은 화면에서 두 쪽 모아보기`, `표지는 한 쪽으로 보기` 옵션을 추가했습니다. 기본값은 둘 다 켜짐입니다.
- 기본은 표지 1쪽, 이후 2–3쪽·4–5쪽 순으로 묶습니다. 표지 옵션을 끄면 1–2쪽·3–4쪽으로 짝을 바꿀 수 있습니다.
- 우→좌 읽기에서는 앞쪽 페이지를 오른쪽, 뒤쪽 페이지를 왼쪽에 놓습니다. 좌→우 읽기도 지원합니다.
- 장이 다르거나 중간 페이지가 빠진 경우, 장 이동 안내 페이지, 이미 두 쪽으로 스캔된 넓은 이미지는 다른 페이지와 묶지 않습니다.
- 두 이미지가 실제로 로드된 뒤 뒷쪽 페이지까지 읽기 진행을 반영합니다. 각 페이지의 확대·이미지 재시도 기능을 유지합니다.
- 창 크기 변경은 원래 페이지 객체를 기준으로 위치를 복원합니다. 세로 넘김·웹툰 모드는 원래 한 쪽 보기로 유지합니다.
- 현재 자동 기준은 창 너비 600dp 이상 및 높이 480dp 이상입니다. 폴드8의 실제 물리 해상도를 가정한 수치가 아니라 앱 창의 크기 기준입니다. 멀티윈도우·화면 확대 설정·실기기 결과에 따라 조정할 수 있습니다.

## 현재 검증 범위와 한계

실행 완료:

- 실제 앱에 사용하는 Java 페이지 묶음·창 크기 정책을 JDK 17로 컴파일하고 실행했습니다.
- 페이지 누락·중복·순서·표지·짝 이동·장 경계·넓은 이미지·읽기 방향·접힌 화면의 가로 회전·분할 창을 검사했습니다. 무작위 500개 시나리오를 포함해 199,827개 단언이 통과했습니다.
- 별도 앱 ID 금지, 개인 브랜딩, 실제 최신·인기 API 연결, 창 변경 시 앵커 복원, 각 목록의 재시도·스크롤 연결을 확인하는 정적 통합 검사 5개가 통과했습니다.
- 변경 파일의 공백 검사와 신규 Android XML 파싱이 통과했습니다.

아직 완료하지 못한 것:

- 작업 환경에 Android SDK가 없고 Gradle 다운로드가 `Network is unreachable`로 실패하여 앱 전체 Kotlin/Compose 컴파일, Android 단위 테스트, 서명 APK 생성은 실행하지 못했습니다.
- 따라서 Compose 화면의 실제 렌더링, 앱 설치, 기존 백업 복원, 실제 확장 재생과 폴드8 접기·펼치기는 아직 검증되지 않았습니다.
- 위 독립 검사 통과는 APK 빌드 성공이나 휴대폰 동작 보증을 의미하지 않습니다.
- 비공개 GitHub 저장소 생성도 자동 승인 검토에서 거부되어, 원격 빌드용 저장소는 생성하지 않았습니다.

## 직접 빌드할 경우

필요 환경: JDK 17, Python 3, Bash, Android SDK 36, Build Tools 35.0.1, Gradle·Maven·Google 저장소 다운로드가 가능한 네트워크.
Android Studio에서 SDK를 설치하고 `ANDROID_HOME`을 설정한 뒤 압축을 푼 프로젝트 루트에서 실행합니다.

```sh
bash tools/test-personal.sh
python3 tools/build-personal.py --check
python3 tools/build-personal.py
```

빌드 스크립트는 휴대폰 앱을 설치하거나 삭제하지 않습니다.
최초 정상 빌드 때 개인 서명 키를 `personal/signing/`에 생성합니다. 이 폴더는 git에서 제외되며 공개 저장소에 올리면 안 됩니다.
이후 개인 APK 업데이트에는 **같은 키와 같은 앱 ID**가 필요하므로 이 폴더를 안전하게 보관하세요.
정상적으로 서명된 APK가 만들어지면 `personal/output/Dtoon-fold8.apk`와 SHA-256 검증 파일이 생성됩니다. 서명되지 않은 APK를 결과물로 복사하지 않습니다.

## 기존 앱을 실제로 교체할 때

공식 애니요미의 서명 키는 보유하지 않습니다. 같은 앱 ID라도 서명이 다르면 기존 공식 앱 위에 바로 업데이트할 수 없습니다.
실제 설치 단계에서는 **기존 앱의 백업 파일과 다운로드 위치를 먼저 확보 → 기존 앱 삭제 → 개인 APK 설치 → 백업 복원**이 필요할 수 있습니다.
설치된 앱이 공식판이 아닌 다른 포크라면 패키지 ID부터 확인해야 합니다.
다운로드 파일은 앱 제거 과정의 저장 위치별 처리 방식에 영향을 받으므로 별도 복사·보관 후 복원 상태를 확인해야 합니다.
현재는 설치 가능한 APK가 없으므로 이 교체 절차를 수행하지 마세요.

## 개인용 릴리스 빌드 호환성

현재 원본 Kotlin 2.4.0과 R8의 메타데이터 호환 경고를 피하기 위해 개인용 빌드 스크립트와 CI는 `-Pdisable-code-shrink`를 사용합니다. 디버그 기능을 켜는 설정은 아니며, 릴리스 APK의 코드/리소스 축소를 끕니다. APK 크기는 최적화 빌드보다 큽니다.

## Dtoon 0.18.2.1-dtoon-fold8.2

- 앱 표시 이름 및 시작 화면/정보 화면 로고를 Dtoon으로 변경했습니다. 타다미의 검정 배경, 보라-하늘색 계열을 참고해 새 D 벡터 로고를 그렸습니다.
- 만화 상세 화면의 회차 목록 위에 연관 추천작을 넣었습니다. 접은 화면 및 두 패널 화면에 모두 표시합니다.
- AniList 연결 ID를 우선 사용하고, 없으면 제목/별칭의 정확한 일치를 확인합니다. 불명확한 검색 결과는 사용자가 기준 작품을 선택합니다.
- 직접 추천이 없을 때는 같은 장르 작품을 별도 표시합니다. 자기 자신/중복/애니/소설은 제외합니다.
- 표지를 누르면 설치된 만화 소스의 통합 검색으로 연결됩니다. 검색 결과는 해당 소스의 제공 여부와 번역 제목에 따라 달라집니다.
- 공개 AniList API에 현재 작품 제목 또는 ID를 전송합니다. 로그인이나 사용자 목록 변경은 필요하지 않습니다. 응답은 최대 48개 키, 6시간 동안 메모리에 보관하고 새로고침 시 다시 요청합니다.
- 추천 조회 실패는 회차 열기나 독서 기능을 차단하지 않습니다. 기존 개인 서명 키와 원본 패키지 ID를 유지해 DaeoYomi에서 업데이트 설치할 수 있습니다.
