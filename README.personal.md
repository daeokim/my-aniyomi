# Dtoon 개인용 폴드 앱 — 구현 및 빌드 안내

서명된 최신 APK는 [Releases](https://github.com/daeokim/my-aniyomi/releases/latest)에 있습니다. Dtoon8.9부터는 앱의 **설정 → 정보 → 업데이트 확인**에서 새 버전을 직접 받을 수 있습니다.
빌드·서명·단위 테스트는 GitHub Actions에서 확인하지만, 실기기 동작은 아직 검증 범위 밖입니다(아래 "현재 검증 범위와 한계").

## 반영한 조건

| 요구 사항 | 코드의 동작 |
|---|---|
| 기존 애니요미와 동시 설치 금지 | 원본과 같은 앱 ID `xyz.jmir.tachiyomi.mi`를 유지하고 debug·preview·benchmark의 별도 ID 접미사를 제거 |
| 개인용 앱 | 이름 Dtoon, 별도 아이콘, 공식 저장소 대신 이 저장소의 Releases로 업데이트 확인, arm64 전용 APK 빌드 |
| 최신·인기 한눈에 | 영상·만화의 각 소스에 기본 최신·인기 개요 화면 추가. 두 실제 목록을 독립적으로 요청하고 한 화면에 표시 |
| 접힌 화면 | 최신·인기를 위아래로 배치. 작은 표지 그리드, 각 목록 독립 스크롤·재시도·전체 보기 |
| 펼친 화면 | 넓고 충분한 높이가 있는 창에서는 최신·인기를 좌우로 배치. 전환 시 두 그리드의 스크롤 상태 유지 |
| 만화 두 쪽 모아보기 | 가로 페이지 뷰어에서 서로 다른 두 페이지를 나란히 표시. 좁은 창으로 바뀌면 한 쪽 표시 |

## 두 쪽 보기의 세부 동작

- 설정 → 만화 뷰어의 읽기 모드 설정에 `넓은 화면에서 두 쪽 모아보기`, `표지는 한 쪽으로 보기` 옵션을 추가했습니다. 기본값은 둘 다 켜짐입니다.
- 기본은 표지 1쪽, 이후 2–3쪽·4–5쪽 순으로 묶습니다. 표지 옵션을 끄면 1–2쪽·3–4쪽으로 짝을 바꿀 수 있습니다.
- 우→좌 읽기에서는 앞쪽 페이지를 오른쪽, 뒤쪽 페이지를 왼쪽에 놓습니다. 좌→우 읽기도 지원합니다.
- 장이 다르거나 중간 페이지가 빠진 경우, 장 이동 안내 페이지, 이미 두 쪽으로 스캔된 넓은 이미지는 다른 페이지와 묶지 않습니다.
- 두 이미지가 실제로 로드된 뒤 뒷쪽 페이지까지 읽기 진행을 반영합니다. 각 페이지의 확대·이미지 재시도 기능을 유지합니다.
- 창 크기 변경은 원래 페이지 객체를 기준으로 위치를 복원합니다. 세로 넘김·웹툰 모드는 원래 한 쪽 보기로 유지합니다.
- 현재 자동 기준은 창 너비 600dp 이상 및 높이 480dp 이상입니다. 폴드8의 실제 물리 해상도를 가정한 수치가 아니라 앱 창의 크기 기준입니다. 멀티윈도우·화면 확대 설정·실기기 결과에 따라 조정할 수 있습니다.

## 현재 검증 범위와 한계

GitHub Actions에서 매 PR과 릴리스마다 확인하는 것:

- 개인 정책 테스트(`tools/test-personal.sh`): 폴드 페이지 묶음 정책 컴파일·실행, 정적 통합 검사, 회차 대응 복원 검사.
- 앱 전체 릴리스 컴파일과 `:app`·`:domain` JVM 단위 테스트.
- 릴리스 때 개인 서명 키로 서명하고 `apksigner`로 서명을 확인한 APK만 게시. 서명되지 않은 APK는 게시하지 않습니다.

아직 확인하지 않은 것:

- 폴드 기기에서 접기·펼치기 전환, 두 쪽 보기, 회차 대응 화면 상태 유지.
- 실제 확장 소스의 검색·재생, 진행도 복사 후 트래커 반영, 앱 내 업데이트 설치 흐름.
- 위 단위 테스트 통과는 휴대폰 동작 보증이 아닙니다.

## 버전 이름과 릴리스

- 버전 이름은 `Dtoon<주>.<부>` 형식(예: `Dtoon8.9`)이고, 같은 이름이 릴리스 태그가 됩니다. 이전 릴리스는 `v0.18.2.1-dtoon-fold8.8` 형식입니다.
- 앱 내 업데이트 확인은 이 저장소의 최신 릴리스 태그와 설치된 버전 이름의 `<주>.<부>`를 숫자로 비교합니다. `fold8.8` 같은 이전 이름도 같은 방식으로 읽습니다.
- 새 버전을 내려면 `app/build.gradle.kts`의 `versionCode`와 `versionName`을 올리고, 이 문서에 `## <versionName>` 섹션을 추가해 `main`에 반영합니다. 그 섹션이 릴리스 노트와 앱 업데이트 안내에 그대로 들어가며, 섹션이 없으면 릴리스 워크플로가 빌드 전에 멈춥니다.

## 직접 빌드할 경우

필요 환경: JDK 17, Python 3, Bash, Android SDK 36, Build Tools 35.0.1, Gradle·Maven·Google 저장소 다운로드가 가능한 네트워크.
Android Studio에서 SDK를 설치하고 `ANDROID_HOME`을 설정한 뒤 압축을 푼 프로젝트 루트에서 실행합니다.

```sh
bash tools/test-personal.sh
python3 tools/build-personal.py --check
python3 tools/build-personal.py
```

빌드 스크립트는 휴대폰 앱을 설치하거나 삭제하지 않습니다.
최초 정상 빌드 때 개인 서명 키를 `personal/signing/`에 생성합니다. 이 폴더는 git에서 제외되며 공개 저장소에 올리면 안 됩니다.
이후 개인 APK 업데이트에는 **같은 키와 같은 앱 ID**가 필요하므로 이 폴더를 안전하게 보관하세요.
정상적으로 서명된 APK가 만들어지면 `personal/output/Dtoon-fold8.apk`와 SHA-256 검증 파일이 생성됩니다. 서명되지 않은 APK를 결과물로 복사하지 않습니다.

## 기존 앱을 실제로 교체할 때

공식 애니요미의 서명 키는 보유하지 않습니다. 같은 앱 ID라도 서명이 다르면 기존 공식 앱 위에 바로 업데이트할 수 없습니다.
실제 설치 단계에서는 **기존 앱의 백업 파일과 다운로드 위치를 먼저 확보 → 기존 앱 삭제 → 개인 APK 설치 → 백업 복원**이 필요할 수 있습니다.
설치된 앱이 공식판이 아닌 다른 포크라면 패키지 ID부터 확인해야 합니다.
다운로드 파일은 앱 제거 과정의 저장 위치별 처리 방식에 영향을 받으므로 별도 복사·보관 후 복원 상태를 확인해야 합니다.
이미 Dtoon(또는 같은 개인 키로 서명된 DaeoYomi)이 설치되어 있다면 이 절차 없이 새 APK를 그대로 업데이트 설치하면 됩니다.

## 개인용 릴리스 빌드 호환성

현재 원본 Kotlin 2.4.0과 R8의 메타데이터 호환 경고를 피하기 위해 개인용 빌드 스크립트와 CI는 `-Pdisable-code-shrink`를 사용합니다. 디버그 기능을 켜는 설정은 아니며, 릴리스 APK의 코드/리소스 축소를 끕니다. APK 크기는 최적화 빌드보다 큽니다.

## Dtoon 0.18.2.1-dtoon-fold8.2

- 앱 표시 이름 및 시작 화면/정보 화면 로고를 Dtoon으로 변경했습니다. 타다미의 검정 배경, 보라-하늘색 계열을 참고해 새 D 벡터 로고를 그렸습니다.
- 만화 상세 화면의 회차 목록 위에 연관 추천작을 넣었습니다. 접은 화면 및 두 패널 화면에 모두 표시합니다.
- AniList 연결 ID를 우선 사용하고, 없으면 제목/별칭의 정확한 일치를 확인합니다. 불명확한 검색 결과는 사용자가 기준 작품을 선택합니다.
- 직접 추천이 없을 때는 같은 장르 작품을 별도 표시합니다. 자기 자신/중복/애니/소설은 제외합니다.
- 표지를 누르면 설치된 만화 소스의 통합 검색으로 연결됩니다. 검색 결과는 해당 소스의 제공 여부와 번역 제목에 따라 달라집니다.
- 공개 AniList API에 현재 작품 제목 또는 ID를 전송합니다. 로그인이나 사용자 목록 변경은 필요하지 않습니다. 응답은 최대 48개 키, 6시간 동안 메모리에 보관하고 새로고침 시 다시 요청합니다.
- 추천 조회 실패는 회차 열기나 독서 기능을 차단하지 않습니다. 기존 개인 서명 키와 원본 패키지 ID를 유지해 DaeoYomi에서 업데이트 설치할 수 있습니다.

## Dtoon 0.18.2.1-dtoon-fold8.3

- Pinyon Script의 DO 두 글자만 사용하는 새 벡터 아이콘으로 변경했습니다. 하단 장식은 제거했습니다.
- 앱 아이콘·시작 화면·정보 화면의 공통 벡터를 갱신했습니다. 색상은 기존 보라·파랑·하늘색과 검정 배경을 유지합니다.
- 개인 패키지와 서명 키를 유지하고 versionCode를 13203으로 올렸습니다.
- 이 릴리스는 브랜딩 변경입니다. 별도 개선 계획의 탐색 탭·이어보기 등 기능 재설계는 아직 반영하지 않았습니다.

## Dtoon 0.18.2.1-dtoon-fold8.6

- 회차 대응·진행도 복사 화면의 상태를 화면 모델로 옮겼습니다. 폴드 기기를 접거나 펼쳐 화면이 다시 만들어져도 직접 고른 대응이 유지됩니다.
- 진행도 복사는 앱의 기본 읽음/시청 처리 경로를 사용합니다. 다운로드의 "읽은 후 삭제" 설정을 따르고, 트래커 자동 갱신이 꺼져 있지 않으면 확인 창에서 연결된 트래커에도 반영할 수 있습니다. 트래커는 앞으로만 갱신하고, 북마크만 복사할 때는 건드리지 않습니다.
- 홈 피드는 최신 목록을 지원하지 않는 소스를 6개 자리에서 미리 제외합니다. 이전에는 이런 소스가 매번 오류로 집계돼 5분 캐시가 저장되지 않았습니다.
- 소스 선택·진행도 병합 정책 JVM 테스트 7개를 추가하고, PR 검사를 릴리스와 같은 테스트·컴파일 단계로 바꿨습니다. versionCode 13206.

## Dtoon 0.18.2.1-dtoon-fold8.8

- fold8.7(`release/dtoon-patch7`: 검색 전체 결과, 수동 전체 새로고침·업데이트 목록, 회차 대응 저장 방식 변경 등)과 fold8.6(접기·펼치기 상태 유지, 트래커 반영, 홈 캐시, Releases 자동 배포)을 하나로 합쳤습니다.

- versionCode 13208. fold8.7(13207) 위에 업데이트 설치됩니다.

## Dtoon8.9

- 버전 이름을 `fold8.x`에서 `Dtoon8.9` 형식으로 바꿨습니다. versionCode 13209로 Dtoon 0.18.2.1-dtoon-fold8.8(13208) 위에 업데이트 설치됩니다.
- 앱 내 업데이트 확인을 켰습니다. 설정 → 정보 → 업데이트 확인, 그리고 앱 시작 시(최대 3일에 한 번) 이 저장소의 최신 릴리스를 확인합니다. 공식 Aniyomi 릴리스는 업데이트로 표시하지 않습니다.
- 릴리스 노트에 이 문서의 해당 버전 섹션이 자동으로 들어갑니다. 앱의 업데이트 안내 화면에도 같은 내용이 표시됩니다.
- 설정 → 정보의 GitHub 링크를 이 저장소로 바꾸고, 공식 Discord 링크를 뺐습니다. 공식 웹사이트 링크는 원본 출처로 남겼습니다.
- 설치 안내 문서의 오래된 "APK 없음 · 교체 금지" 문구를 현재 상태에 맞게 고쳤습니다.

## Dtoon9.0

- 홈 화면의 최근 기록을 만들 때 작품마다 DB를 다시 조회하던 것을 줄였습니다. 제목·표지는 기록에 있는 값을 쓰고, 소스 정보는 서재에서 먼저 찾으며 서재 밖 작품만 한 번 조회해 기억합니다. 서재 업데이트 중 홈이 반복 계산될 때의 부담이 줄어듭니다.
- 앱의 화면 언어를 한국어와 영어만 남겼습니다. 다른 언어 번역은 APK에서 빠지고, 설정의 앱 언어 목록에도 두 언어만 표시됩니다. 다른 언어로 설정해 두었다면 영어로 표시됩니다.
- 진행도 복사 화면이 회차 번호가 양쪽에 하나씩만 있는 회차를 미리 짝짓고 "(번호로 제안)"으로 표시합니다. 번호가 겹치거나 없는 회차는 이전처럼 직접 고릅니다. 저장된 대응이 있으면 그것을 먼저 씁니다.
- versionCode 13210. Dtoon8.9에서는 앱의 업데이트 확인으로 받을 수 있습니다.

## Dtoon9.1

- 업데이트 탭: 회차를 한 번도 불러오지 않은 채 보관함에 추가한 작품(탐색 목록에서 길게 눌러 추가 등)은 처음 회차를 불러올 때 기존 회차를 업데이트로 세지 않습니다. 업데이트 목록·배지·알림에 기존 회차가 새 회차처럼 나오지 않고, "새 회차 자동 다운로드"가 기존 회차를 한꺼번에 받지 않습니다. 애니도 같습니다. 그 뒤 새로 나온 회차부터 업데이트로 표시됩니다.
