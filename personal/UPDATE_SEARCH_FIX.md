# 업데이트 목록 / 검색 취소 수정

## 변경
- 만화 업데이트 탭은 보관함 작품별로 소스 순서상 최신 회차 한 개만 표시합니다.
- 최신 회차 선택은 500개 제한 전에 수행합니다. 뒤늦게 수집된 구회차가 최신 회차를 대체하지 않습니다.
- 기존 최근 3개월 조건과 보관함 등록 이후 수집 조건은 유지합니다.
- 다른 회차는 삭제하지 않으며 작품 상세에서 계속 볼 수 있습니다. 자동 다운로드와 알림의 전체 회차 정책도 유지합니다.
- 만화 소스 검색 취소, 초기화(X), Android 뒤로가기 시 제출된 검색 조건도 해제합니다.
- 탭/요일/필터는 유지하고 검색 조건에 맞는 페이징 흐름을 다시 연결합니다.
- 공용 카탈로그의 캐시 키에 필터/검색 키를 포함합니다. 이 부분은 만화·애니 카탈로그 모두에 적용됩니다.

## 검증
- 수정 전 새 SQLite 초기 회귀 테스트 8개 중 6개 실패, 보완 후 총 10개 통과.
- 기존 정적 통합 검사 5개 통과.
- 검색 상태 JUnit 테스트 6개 추가: 닫기, 초기화, 입력 중, 기본 목록, 반복 취소.
- 현재 Android 환경에 Java/Android SDK가 없어 Gradle 및 JUnit 실행과 APK 빌드는 미완료입니다.
- 설치/기기 데이터 변경/원격 저장소 업로드는 수행하지 않았습니다.

## 빌드 환경에서 실행

원본의 비공개 Actions 워크플로도 위 테스트를 실행하도록 연결되어 있습니다.

## 기기 검증
1. 등록 만화에 여러 구회차가 있어도 업데이트에는 최신 한 회차만 나오는지 확인.
2. 네이버웹툰 인기/최신 탭에서 검색 후, 결과가 있는 경우와 없는 경우 각각 검색창 뒤로가기로 닫기.
3. X로 입력을 지우고 기본 목록이 복원되는지 확인. Android 뒤로가기에서도 동일하게 확인.
4. 요일/완결 필터를 선택하고 검색·취소 후 해당 탭과 필터가 유지되는지 확인.

## 한계와 추가 개선
- 최신 회차는 Aniyomi 확장 계약(최신순 회차 반환)의 source_order를 기준으로 합니다.
- 네이버웹툰 확장 자체의 서버 응답/로그인 문제는 별도 실기기 확인이 필요합니다.
- 앱 전체 빌드가 미검증이므로 제공물은 수정 소스이며 설치용 APK가 아닙니다.
- README.personal.md의 과거 빌드 상태와 현재 릴리스 설명을 향후 정리할 수 있습니다.

## 추가 검토 결론
- StateFlow.update 내부의 revision 증가를 제거했습니다. 이 콜백은 재시도될 수 있으므로 상태 변환만 수행합니다.
- 페이징 재연결은 검색 조건을 포함한 filterKey 변경으로 수행합니다.
- 최신화 쿼리는 SQLite 실행 계획에서 작품별 최신 회차 선택 후 챕터 PK 조회로 최적화됩니다.
- 테스트 fixture 30작품 × 300회차, manga_id 인덱스에서 약 1.14ms였습니다. 실제 폰 성능 보장은 아닙니다.
- 현 단계에서는 복합 인덱스/DB 마이그레이션/설정 토글/애니 업데이트 정책 변경은 추가하지 않습니다.
- 별도 코드 검토 에이전트도 쿼리 유지와 신규 Kotlin 테스트 의존성/타입 구성을 검토했습니다. Kotlin 컴파일 성공을 뜻하지 않습니다.
- 이후 Claude·Gemini의 그룹 검토 의견을 수신해 아래 항목을 소스로 확인했습니다.
- 원본과 CREATE VIEW 정의는 바이트 기준 동일하며 getRecentUpdates 실행 쿼리만 변경했습니다. 기존 설치 DB의 뷰를 바꾸지 않으므로 이번 수정에 .sqm 마이그레이션은 필요하지 않습니다.
- AndroidConfig.MIN_SDK=26. ROW_NUMBER 같은 윈도 함수는 사용하지 않고 기본 SELECT/상관 서브쿼리/ORDER BY/LIMIT만 사용합니다. Android/SQLDelight 빌드 검증은 여전히 필요합니다.
- 전체 선택/읽음/다운로드/삭제/북마크는 현재 화면에 보이는 최신 회차에만 적용됩니다. 숨긴 예전 회차에 자동 확대 적용하지 않습니다.
- 새 업데이트 배지는 MangaLibraryUpdateJob의 newChapters.size 누적으로 계산하므로 작품 행 수와 다를 수 있습니다. 기존 알림/배지 정책을 유지합니다.
- 브랜치에 패치 적용 후 Actions 수동 실행, 테스트/빌드 확인 후 main 병합을 권장합니다. 웹 업로드는 경로 보존 실수가 쉬우므로 Git 패치 방식 권장.
- 자동 서명 CI는 기존 키 확인과 안전한 Secrets 설정 이후의 선택 후속 작업입니다. 키를 생성/업로드하거나 워크플로를 이번 범위에서 변경하지 않았습니다.
- Gemini의 “즉시 복원된다”는 표현은 목표 동작이며, 현재 실제 기기 검증 완료를 의미하지 않습니다.

## 후속 그룹 리뷰 반영
- 최신 회차 선택은 전체 chapters에서 수행하며, 최신 회차가 등록 전 수집되었거나 업로드 날짜 범위 밖이어도 구회차로 fallback하지 않습니다. 등록 전 수집 최신 회차/날짜 기준 테스트를 추가해 SQL 테스트는 총 10개입니다.
- 기존 3개월 조건은 dateUpload 기준입니다. dateFetch 기준으로 변경하지 않았습니다.
- 만화 State에 catalogFiltersSnapshot을 추가했습니다. 초기 복원/필터 적용/장르 검색 때만 갱신하고, 시트 편집/초기화 중에는 활성 목록 조건을 바꾸지 않습니다.
- 검색 취소에서도 적용된 snapshot을 유지합니다. 편집/초기화/취소 상태 테스트를 추가해 JUnit 테스트는 총 6개이며 실행은 미완료입니다.
- 애니 모델까지 동일한 필터 draft 분리 수정은 확대하지 않았으며 GPT Work에서 공용 카탈로그 회귀를 확인해야 합니다.
